# 書庫 MCP拡張機能（.mcpb）

Claude Desktopから、noteなどのブログバックアップを検索・閲覧できるようにする拡張機能です。

書庫アプリとは独立して動きます。アプリのインストールも起動も不要です。WXRの解析とMarkdown変換はアプリ（`Sources/WXRReader/WXRParser.swift`、`HTMLToMarkdown.swift`）からの移植なので、読み取る内容はアプリと一致します。検索の並び順だけは、目で一覧を眺めるアプリと、限られた件数しか見ないClaudeとで求められるものが違うため、この拡張機能側で作り直しています（後述）。

## インストール

1. [Releases](https://github.com/tanuu5/WXRReaderMac/releases) から `shoko.mcpb` をダウンロード
2. ダブルクリック（またはClaude Desktopのウィンドウにドラッグ＆ドロップ）
3. インストール画面で「バックアップフォルダ」に、noteのバックアップを展開したフォルダを指定
4. インストール

設定ファイル（`claude_desktop_config.json`）を手で編集する必要はありません。Claude Desktopが必要な設定を自分で書き込みます。

## バックアップを更新したとき

**何もしなくて構いません。** noteから取り直したバックアップでフォルダの中身を入れ替えるだけです。

ファイルの更新時刻とサイズが変わったことをサーバが検知して、次の検索から自動的に新しい内容を読みます。手元の実データ相当（10ファイル・約18MB・1008記事）で読み込みは約0.13秒なので、待たされる感覚はないはずです。

## 使用例

- 「書庫にClaude関係の記事どれくらいある?」
- 「去年書いたSwiftの記事を探して、内容をまとめて」
- 「『バイブコーディング』について前に何を書いたか教えて」
- 「2026年前半に書いた記事のタイトルを全部出して」
- 「今度こういう記事を書こうと思うんだけど、前に同じネタ書いてない?」
- 「AIの料金の話、自分はいつ何を言ってきた? 主張は変わってる?」

## なぜMCPなのか（1000本のブログを扱うために）

記事が1000本を超えると、Claudeにフォルダを渡して読ませる方式は成立しません。バックアップは記事ごとにファイルが分かれておらず、1つの.xmlに100記事ほどがまとまっているためです。1本読みたいだけでも、それが入っているファイルを丸ごと開くことになります。

この拡張機能では、XMLを読んで解析するのはサーバのプロセスです。Claudeに渡るのはツールが返した結果だけで、全文が送られるわけではありません。手元の蔵書（1008記事・本文合計447万字）と同規模のデータでの実測値は次のとおりです。

| 操作 | ツールが返した文字数 |
| --- | ---: |
| `library_info`（蔵書の概要） | 432字 |
| `find_similar`（近い記事10件） | 923字 |
| `topic_timeline`（40件を時系列で） | 3,180字 |
| `get_article`（記事1本の全文） | 4,321字 |
| `search_articles`（既定の20件） | 6,477字 |
| 参考：全記事本文の合計 | 約448万字 |

検索1回が蔵書全体の約700分の1で済みます。これがMCPを挟む理由です。

実際に消費されるのはトークン数であって文字数ではないため、上の数字は比率の目安として見てください。

`limit` の上限を50に抑えているのも同じ理由です。該当が多いときは全件を取ろうとせず、`date_from` / `date_to` で絞るか、検索語を具体的にしてください。上限を超えた場合はサーバがその旨を応答に添えます。

## ツール

| ツール | できること |
| --- | --- |
| `library_info` | 記事数、期間、投稿タイプ、よく使うカテゴリ・タグの概要 |
| `search_articles` | 検索。スペース区切りでAND、`OR` でOR。関連度順に並ぶ。期間・投稿タイプで絞り込み |
| `find_similar` | ある文章に近い過去記事を探す。重複チェックと関連記事の両方に使う |
| `topic_timeline` | ある話題をいつ何を書いてきたか、古い順に並べる |
| `get_article` | 記事1件の本文取得。`markdown` / `html` / `text` を選べる |

### 検索の並び順

蔵書が1000本あると、絞り込むだけでは足りません。たとえば「Claude」はこの書庫の約半分の記事に出てくる語で、該当を新しい順に並べても、探している記事が上位に来る理由がどこにもありません。

そこで既定を関連度順にしています。基準は2つ。**珍しい語ほど重く見る**（`Claude 料金` なら、書き手が毎日使う「Claude」より「料金」が順位を決める）。**タイトルに出る語を重く見る**（本文で一度触れただけの記事より、それを主題にした記事を上に置く）。本文中の出現回数も見ますが、長い記事が有利にならないよう頭打ちにしています。

日付順に戻したいときは `sort: "date"` を指定してください。検索語を空にして絞り込みだけを行う場合は、順位のつけようがないので自動的に日付順になります。

抜粋（`snippet`）は、検索語がもっとも集まっている箇所を切り出します。最初の1語の初出だけを見ると、常用語のせいでどの記事も同じ書き出しが返ってきてしまうためです。

検索前に表記を NFKC で正規化するので、`ＡＩ` と `AI`、`ｻｰﾊﾞ` と `サーバ` は同じものとして扱われます。

### 重複チェックと関連記事（`find_similar`）

これから書く記事の題材を `text` に渡すと、同じネタを過去に書いていないか調べます。検索語を思いつく必要がないのが利点で、1000本のうち自分でも忘れている記事を拾えます。既存記事を `id` で渡せば、そのまま関連記事や自己引用リンクの候補になります。

点数は「渡した文章の特徴語のうち、その記事がどれだけ共有しているか」の割合です。応答には `confidence`（high / low / none）と点数の意味も添えてあるので、そちらを見て判断してください。

判定は語の一致に基づくので、同じ題材を別の言い回しで書いていれば見落とします。何も返らなかったときも「書いていない」と断定はせず、題材の固有名詞で `search_articles` を引いて裏を取るのが確実です。

### カテゴリ・タグについて

**noteのバックアップにはカテゴリ・タグが含まれていません**（エクスポート形式の仕様で、書庫アプリでも同様に空になります）。noteが元データの場合、`tag` と `category` での絞り込みは効きません。この場合 `library_info` がその旨を応答に添えるので、Claudeが使えない絞り込みを試すことはありません。WordPressのエクスポートには含まれるため、その場合は機能します。

## プライバシー

この拡張機能自体は、ファイルの読み取りしか行いません。書き込みも、独自の外部通信もしません。XMLの解析と検索はすべてお使いのMac内で完結します。

ただし、**ツールが返した検索結果や記事本文は、Claudeとの会話に使われるためAnthropic側へ送られます**。手元で完結するのは検索までで、その先は通常のClaudeの利用と同じです。蔵書全体が送られるわけではなく、送られるのはヒットした分だけ、という点が違いです。

## 開発

依存パッケージはありません。Node標準ライブラリのみで動きます。

```bash
# 動作確認（読み込めるか、記事数は合っているか）
SHOKO_WXR_DIR=/path/to/backup node server/index.js --selftest

# .mcpb を作る
./pack.sh
```

`pack.sh` は `@anthropic-ai/mcpb` をnpx経由で呼び、`../build/shoko.mcpb` を出力します。

構成:

```
mcpb/
  manifest.json     # 拡張機能の定義（ツール一覧・フォルダ選択UIの定義）
  server/index.js   # MCPサーバ本体（WXR解析・検索・Markdown変換）
  icon.png
  pack.sh
```

## 変更履歴

### v1.1.1

v1.1.0を手元で試したところ、`find_similar` に日本語だけの文章を渡すとほぼ何も返らないことが分かりました。原因は「語の長さで重みを割る」処理で、**日本語の一文は句読点まで文字コードが連続しているため、文全体が1語として数えられていた**ことです。100字のメモが1/99ずつに薄まり、実質ラテン文字の語しか効いていませんでした。

- 語の区切りを、文字種（ひらがな・カタカナ・漢字・英数字）の変わり目で判定するよう修正。辞書は使いません
- 一文字の漢字を照合から除外。本文4400字への部分一致では当たって当然で、雑音にしかならないため
- 本文にしか出てこない語も照合するよう変更。題材に触れていてもタイトルには出さない記事を拾うため
- 点数を「渡した文章の特徴語のうち何割を共有しているか」の割合に変更し、`confidence` と点数の意味を応答に添えるようにした
- 該当なしのときに「過去記事はない可能性が高い」と断定するのをやめた。語の一致で探している以上、言い回しが違えば見落とすため
- `sort` に有効値を明示。「最近」を聞かれたときは日付順か期間指定を使うよう、説明文に明記
- `topic_timeline` は15件以下なら抜粋も返すようにし、説明文の「主張の変化を追える」という過剰な約束を撤回。これは一覧であって答えではありません

（手元での確認のみ。上の不具合があるため公開していません）

- 検索を関連度順に変更（語の珍しさとタイトル一致で重み付け）。`sort: "date"` で従来の日付順に戻せます
- `find_similar` を追加。重複チェックと関連記事の候補出しに使えます

- カテゴリ・タグが空の蔵書では、その旨を `library_info` の応答に添えるよう変更。使えない絞り込みをClaudeに試させないため
- タイトルのHTML実体参照（`&quot;` など）を復元するよう修正
